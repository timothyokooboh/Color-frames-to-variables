# Domain docs

Use a single-context layout:

- GLOSSARY.md at the repository root.
- Architecture decision records in docs/adr/.

Before exploring the codebase, read the glossary and any ADRs
relevant to the work. If absent, proceed silently; create them
through domain-modeling as terms and decisions are resolved.

Use the glossary's terminology. Explicitly flag proposals that
conflict with an existing ADR.
